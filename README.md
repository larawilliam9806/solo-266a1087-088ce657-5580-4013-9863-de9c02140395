# 电量日核算（Flask + SQLite）

电网数据员上传晚到的电表累计读数与换表记录，系统按计量点把相邻读数连成区间，
自动算出可核算的逐日用电量，并标记换表造成的缺口区间。
馈线转供后，还可在线损核查页整份上传接线台账，按总表和 UTC 日逐时段核对线损，
分清哪些时段可以核算、哪些还要补采。

## 业务规则

- **读数 CSV**（表头 `point,ts,value`）：计量点、UTC 时刻（ISO 8601，须带 `Z` 或 `+00:00`）、
  非负十进制千瓦时累计读数。
- **换表 CSV**（表头 `point,ts`）：计量点、UTC 换表时刻。
- **幂等**：同点同刻同值的原样重传自动跳过，不重复计数；
  同点同刻**不同值**（文件内或对比既有数据）→ 整批拒绝。
- **区间计量**：每个计量点按时刻连接相邻读数构成区间 `(t1, t2]`：
  - 区间内发生换表（`t1 < s <= t2`，**含后次读数时刻**）→ 标记缺口，不推算增量；
  - 否则增量 = 后次 − 前次，计入**后次读数所属 UTC 日**；
  - 增量为负（读数倒退）→ 整批拒绝。
- **晚到读数**插入后自动拆分旧区间，增量按新区间重新归属。
- **补录换表**后，原区间变为缺口，此前计入的增量自动撤销。
- **事务性**：一次上传的原始记录与其影响的日结果在同一事务内生效；
  任何校验失败整体回滚，保持旧数据；被拒批次留有审计记录。
- **并发一致性**：SQLite WAL 模式；上传用 `BEGIN IMMEDIATE` 串行化，
  查询在单个读事务内完成，页面只能看到同一版本的完整结果（页面右上角显示数据版本号）。

## 线损核查

- **台账 CSV**（表头 `master,sub,start,end`）：总表、分表、UTC 起止时刻。
  在线损核查页**整份上传、全量替换**；校验或保存失败时保留原台账。
- **台账校验**：接线时段左闭右开 `[start, end)`（须 `start < end`）；
  同一分表的时段不得重叠（端点相接不算重叠）；
  同一时刻一块表不能兼作总表和分表（含同一行总表 = 分表）。
- **时段划分**：选择总表和 UTC 日后，把 `[当日零时, 次日零时)` 按分表集合的变化
  划分时段（相邻且分表集合相同的区间合并），跨天的接线时段裁剪到当日。
- **逐段核对**：某段有接线、总表与所有在接分表在时段两端均有实测读数、
  且段内无换表（`起点 < 换表时刻 <= 终点`，含右端、不含左端）时，
  显示 **总表增量 − 各分表增量之和**（保留差额正负）；
  其余时段指出未接线、缺读或换表的位置，列出相关表计和时刻。
- **全天差额**：全天各段均可核对时才显示全天差额。
- **核查范围**：只读取相关表计（总表 + 当日涉及的分表）从当日零时到次日零时（含）
  的读数和换表记录；单次核查在**同一个读事务快照**内完成，
  核查期间上传不受阻塞，重新核查即反映已提交的更新。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。数据持久化在命名卷 `meter-data`（容器内 `/data/app.db`）。

### 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python run.py                 # 默认 0.0.0.0:8000（waitress）
pytest tests/                 # 运行测试
```

环境变量：`APP_DATABASE`（SQLite 路径，默认 `./data/app.db`）、`PORT`（默认 8000）、
`SECRET_KEY`、`USE_WAITRESS=0` 可退回 Flask 内置服务器。

## 页面与接口

- `GET /` — 上传入口、查询入口、最近上传批次（含被拒原因）。
- `POST /upload/readings`、`POST /upload/swaps` — 表单上传 CSV（字段名 `file`）。
- `GET /usage?point=..&start=..&end=..` — 逐日用量表 + 缺口区间；日期缺省时取该点数据最近 31 天。
- `GET /api/usage?point=..&start=..&end=..` — 同口径 JSON（含数据版本号），便于核对与集成。
- `GET /loss?master=..&day=..` — 线损核查页：台账上传（整份替换）、当前台账、逐时段核对结果；
  日期缺省时取今天（UTC）。
- `POST /upload/ledger` — 表单上传台账 CSV（字段名 `file`），整份替换。
- `GET /api/loss?master=..&day=..` — 同口径 JSON（含数据版本号）：
  每段给出 `status`（`ok` / `unwired` / `blocked`）、差额或问题清单（缺读/换表的表计与时刻），
  全天可核对时给出 `total_diff`。

## 实现说明

- 读数以文本存十进制（`Decimal` 计算），时刻规范化为定宽 UTC 字符串（字典序即时间序）。
- 日用量不做冗余物化：查询时在单事务内由原始记录现算，
  因此“原始记录”和“受影响日结果”天然同事务生效，晚到读数/补录换表的影响即时可见。
- 台账整份替换在同一事务内“先清空再写入”，失败整体回滚，原台账不变；
  线损核查在单个读事务内读取台账、读数与换表记录，三者必然来自同一快照。
- 代码结构：`app/logic.py`（解析、校验、区间/日用量计算、台账与线损核查）、
  `app/routes.py`（页面与 API）、`app/db.py`（连接与建表）、`tests/test_app.py`（规则与并发测试）。
